# Same-room live PeerJS POC

This is a static browser prototype for comparing live microphone audio from two
PeerJS-connected browsers. `exports/compare/compare.js` owns microphone
permission, raw capture, timestamped packet preparation, packet history, and
WASM scoring in its worker. PeerJS carries only compact timestamped feature
packets and score results; raw microphone audio is never sent to the other
device.

The connected view shows the most recently prepared local packet and the most
recent packet returned by a score request. If a request cannot be delivered or
answered, the page reports that transport failure rather than treating the
pair as unrelated.

The page uses the `peer-code` query parameter for invite links. The displayed
QR code is generated by the QR Server API and contains the complete invite URL.

## Local run

From the repository root:

```powershell
python -m http.server 3000
```

Open `http://localhost:3000/web-peer-demo/`. For two devices, deploy this folder over HTTPS or
use an HTTPS development host; microphone permissions require a secure context
outside localhost.

Live scoring is request-driven. The model window and minimum input length are
loaded from `model.json`; the page asks `AudioCompare.pipeMicAudio()` to capture
raw samples locally without preparing packets continuously. Pressing
`Request Score` prepares and sends one timestamped packet to the peer. The peer
prepares its current packet, compares the pair, and returns that packet and
score. The requesting device compares the returned pair too, so both devices
score the same exchange. The connected view renders the serialized 40-band mel payload
from each local/remote packet as a heatmap, along with its frame count, level,
activity, and quantization mode. This uses packet bytes already exposed to the
demo through `AudioCompare.drawPacket()`; it does not add raw audio or extra
fields to `AudioCompare`.

The PeerJS connection uses ordered reliable delivery for each explicit request.
The host sends its current synchronized timestamp when the connection opens so
both packet histories use the same clock. A request is rejected if the nearest
packet timestamp differs by more than 2.5 seconds.
